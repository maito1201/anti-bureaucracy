# thorough-task

ユーザーがこの進め方を選んだ仕事で、節目ごとに検証する。通常の仕事には、この検証の繰り返しを求めない。

## 適用条件

- 今回の仕事について、この進め方へのユーザーの同意、またはこのスキルの明示的な指定を確認する。アウトカムへの同意だけでは、この進め方への同意とはみなさない。
- 同意がなければ、このスキルと review-outcome は実行しない。すでに断られていれば再提案しない。返答がない場合も同意とはみなさない。
- 同意は今回の仕事に限る。ユーザーが通常の進め方に戻すよう指示したら従う。節目ごとに承認を取り直す必要はない。

## 進め方

1. 合意したアウトカムと既存の制約を引き継ぐ。目的について決まっていない点だけを確認する。この進め方のために、別の計画書や管理台帳は作らない。
2. 次の工程に進むために何が成り立っている必要があるかを考え、検証するタイミングを短く伝える。設計から実装へ進む前や、本格的な学習・実験を始める前など、前提が誤っていると結果が無効になる箇所を選ぶ。編集やツールの呼び出しのたびには検証しない。
3. そのタイミングで skill `review-outcome`（[review-outcome](../review-outcome/SKILL.md)）を読み、目的を満たしていない点を報告してから、修正と再検証を行う。次の工程に必要な前提を確認できたら先に進む。
4. 期待と異なる結果が出たときも、同じように見直す。ただし、直前の検証で同じ前提と成果物を確認済みで、その後に変更や新しい観測結果がなければ、繰り返さない。
5. 完了を報告する前に、最終成果物を同じ方法で見直す。直前の見直しで最終成果物がアウトカムを満たすことを確認済みなら、その検証結果を使う。満たしていなければ修正に戻り、続けられない場合は review-outcome の中断条件に従う。

通常のテスト・lint・必要な承認は、既存の規約に従う。この進め方への同意があっても、目的の変更や予算・権限の追加には別の同意が必要である。
