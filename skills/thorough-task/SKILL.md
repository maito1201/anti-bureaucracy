# thorough-task

通常の仕事に検証の反復を持ち込まず、本人が選んだ仕事だけを丁寧に進める。

## 入る条件

- 今回の仕事について、丁寧に進める提案へのユーザーの同意、またはこのスキルの明示的な指定を確認する。アウトカムへの同意だけを、この進め方への同意とみなさない。
- 同意がなければこのワークフローと review-outcome は実行しない。既に辞退されていれば再提案しない。無回答のまま同意したことにしない。
- 同意は今回の仕事に限る。ユーザーが通常の進め方へ戻すよう指示したら戻る。節目ごとの再承認は求めない。

## 仕事を進める

1. 合意したアウトカムと既存の制約を引き継ぐ。未確定の目的だけを確認する。実行のための別計画書や台帳は作らない。
2. 次の工程が何を前提にするかを見て、検証する節目を短く示す。設計から実装、本学習・本実験への移行など、誤った前提で進むと結果が無効になるところを選ぶ。個々の編集・ツール呼び出しごとには挟まない。
3. その節目で [review-outcome](../review-outcome/SKILL.md) を読み、未達の発見結果を出してから修正・再検証を行う。次工程の前提が成立したら仕事を進める。
4. 期待外れの結果が出た時も同じ再評価を行う。直前の検証で同じ前提と成果物を既に確認していて、新しい変更・観測がなければ重複実行しない。
5. 完了報告前に、最終成果物について同じ再評価を行う。直前の再評価で最終成果物とアウトカムを確認済みなら、その証拠を使う。未達なら修正へ戻り、進められない場合は review-outcome の中断条件に従う。

通常のテスト・lint・必要な承認は既存の規約に従う。この進め方への同意は、目的の変更や追加の予算・権限への同意ではない。
